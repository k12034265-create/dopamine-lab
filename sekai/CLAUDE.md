# 世界のネタバレ 制作・投稿手順

解説チャンネル「世界のネタバレ」（@sekainonetabare、チャンネルID `UCnitdCImoZ2PO3ZSo4J9Pvg`）の長尺動画を作って投稿する手順。オーナーはKOH。
ドーパミンラボ（リポジトリ直下の CLAUDE.md）とは別チャンネル・別Googleアカウント。混ぜないこと。

## 方針（KOH決定）
- お手本は「考えすぎる葦」。型（構成・タイトルの付け方・概要欄の形式）は寄せる。内容はパクらない。
- 当面は恋愛・性・モテ系を多め。少しエロ寄りでよいが、BAN・年齢制限は絶対に避ける（年齢制限で伸びなくなる）。
- **栃木・宇都宮のネタは控えめにする（KOH指定 2026-11-23）。** 地元が特定されるため。11（車）の宇都宮LRTの章はそのまま出すが、次の回からは栃木を主役にしない。地方の例は他県や全国の数字から選ぶ。
- 量産済みのネタと被らないよう、切り口で勝負する。シミュレーション・実データの図解、地方目線のネタも今後増やす。
- 8分以上（ミッドロール広告のため）。**ネタが余る回は10分・12分と伸ばしてよい。無理に8分にまとめない**（KOH指定 2026-11-21）。目標は考えすぎる葦の水準（登録15万人・月数十万円規模）。計画は `sekai/plan.xlsx`。
- ナレーション：VOICEVOX 青山龍星 ノーマル（style id 13）、話速1.1。クレジット「VOICEVOX:青山龍星」を概要欄に必ず入れる。
- 概要欄は**短く**（KOH指定。1本目の約4,800字は長すぎた）。目安1,200字以内。見本は `episodes/01_nioi/desc_short.txt`。
  - 導入2行（問いかけ＋「〜をネタバレします！」）→ ▼目次（タイムスタンプ）→ ▼参考文献（「著者 (年) URL」の1行ずつ。研究の要約・注記は書かない）→ 注意書き1行 → 「音声：VOICEVOX:青山龍星」→ ハッシュタグ。
  - ハッシュタグは**多め**（KOH指定）：概要欄の末尾に8〜10個。16個以上にするとYouTubeが全部無視するので15個未満を厳守。タイトルの上に出るのは最初の3個なので、テーマの主語＋ジャンル＋ #世界のネタバレ を先頭3個に置く。
  - タグ欄（tags.txt、カンマ区切り）は15〜20個・500文字以内。テーマ語・言い換え（例：キス／接吻／口吸い）・固有名詞・ジャンル・#なしのチャンネル名。他チャンネル名など内容と関係ない語は入れない（誤解を招くメタデータは規約違反）。
  - 研究の細かい説明は動画の中で話す。概要欄には書かない。
- 締めのセリフ：「今日のネタバレは、ここまで。よければチャンネル登録と高評価をお願いします。それでは、また次のネタバレで。」

## 進め方（KOH決定）
- **指摘や要望をもらっても、すぐに作り直し・書き出し・アップロードを始めない。** まず「どう直すか」を短く提案して、KOHが「作り直して」「やって」と言ってから手を動かす。
- 提案するときは**目安時間**も必ず添える。目安（このマシン、3D・2本並列で書き出した場合）：
  - 3Dシーン1つの修正＋書き出し：10〜20分 ／ 全50シーンの書き出し：約5〜6時間 ／ 30シーン前後：約3時間半
  - ナレーション音声の作り直し：5分 ／ つなぎ・音合わせ・100MB未満への圧縮：約25分
  - サムネ1案：写真＋文字なら10分、3Dで組むなら30分
  - Studioへのアップロード〜詳細・サムネ入力：15分（＋YouTube側の処理）
  - 新しい回の台本＋音声：1〜2時間

## 映像スタイル

## 制作パイプライン（`sekai/pipeline/`）
新しい作業環境ではまず `bash sekai/setup_voicevox.sh`。
1. `sekai/episodes/NN_テーマ/` を作り、`script.py`（SCENES・REFS・READINGS）と `scenes.js`（各シーンの図解）を書く。01_nioi が見本。
   - SCENES は (パート名, ナレーション, 画面の指示, 出典, 読みメモ) のタプル。パート名が変わったところが章の区切り（タイムスタンプ）。
2. `EP=$PWD/sekai/episodes/NN_xxx bash sekai/pipeline/make.sh tts` で音声 → `EP=... python3 sekai/pipeline/check_reading.py` で実際の読み（カナ）を全文出して目で確認し、読み違いは script.py の READINGS で直す（「は」→ワ、「間」→カン、数字の読みなど） → `snap.py` で数フレームを確認。
3. `make.sh render` → `make.sh mux` で `work/final.mp4`。最後に表示されるタイムスタンプを概要欄に使う。
4. `title.txt` `desc.txt` `tags.txt` をエピソードフォルダに置く。
5. 台本Excelが要るときは `EP=... python3 sekai/pipeline/build_xlsx.py`。
- `work/` は git に入れない（.gitignore）。

## 投稿手順（GitHub方式）
- 内蔵ブラウザ（`mcp__remote-devices__Claude_Browser__*`）で操作。Studio は `?authuser=2`（vivivimhwib アカウント）。
1. `work/final.mp4` を `sekai/videos/NN_xxx.mp4` にコピーして commit & push（100MB未満にする）。
2. Studio のアップロード画面を開き、`sekai/upload.js` の関数を javascript_tool で実行：
   `putFile('https://raw.githubusercontent.com/k12034265-create/dopamine-lab/main/sekai/videos/NN_xxx.mp4','NN_xxx.mp4')`
   → `details(タイトル, 説明, タグ配列)` → `visibility('PUBLIC')`（KOHのOK後。予約ならスケジュール設定）。
   - 注意（02で発生）：ページを開いた直後の fetch は失敗することがある → 数秒待って再実行。ファイル投入後「リンクを作成しています…」のまま止まったら、ページを開き直して投入からやり直す。動画リンク（youtu.be/…）が出てから details を入れる。公開後は編集画面でタイトル・タグ・各設定が保存されたか確認する。
   - サムネ：`sekai/videos/NN_xxx_thumb.jpg` も push しておき、アップロード後に編集画面で `putThumb(rawURL)` → `#save`。（input に直接入れても反応しない。ボタンのクリックで呼ばれる input.click を横取りする）
3. 公開できたら `sekai/videos/` の動画を削除して push。`sekai/log.md` に追記。
4. **後片付け（KOH指定 2026-11-21、毎回やる）：** 投稿（公開 or 予約）とサムネ設定の確認まで終わったら、いらない素材を消す。
   - KOHのMacの `~/Downloads` に落としたフリー素材（`.Q6L2SF6YDW.com.anthropic.claudefordesktop.*` や `p_*.jpg` など、その回で落としたもの）→ device_request_delete_permission で許可をもらって削除。
   - `sekai/videos/` に置いた動画・サムネ、作業用の `work/clips`・試作mp4（`/home/claude/*.mp4`）も削除。
   - 残すもの：台本・シーンのコード・使った写真（`episodes/NN/img/`）・title/desc/tags・サムネのHTMLとjpg。
- **サムネを設定してから公開・予約する（KOH指定 2026-11-21、04で設定漏れ）。** 予約後に編集画面のサムネ欄で自作サムネが入っているか必ず確認する。スタイルは03キス風（実写写真＋グラデ太文字）。
- サムネのHTMLには必ず `<meta charset="utf-8">` を入れる（06で文字化けしたままアップした）。アップ後、編集画面のプレビューで文字が読めるか確認する。raw.githubusercontent はキャッシュされるので、差し替え時はコミットのハッシュ入りURLで取る。
- **公開時刻（KOH指定 2026-11-23）：本編は毎回17:00に予約する。** ショートは同じ日の20:00（本編より後）。
- **ショート動画（KOH指定 2026-11-21）：** 新しい本編を投稿するたびに、一番気になる・面白い部分を30秒前後の縦動画にして一緒に投稿する（予約なら本編の公開より後の時刻）。
- サムネイル：電話番号の確認済み（2026-11-20）。カスタムサムネを使う。作り方は STYLE.md の「サムネイルとタイトル」。サムネ専用の3Dシーン（例：03_kiss/thumb3d.js）を組み、HTMLで文字を重ねる。動画の切り抜きだけで済ませない。

## 送る前の全シーンチェック（2026-11-22 07で品質が落ちた反省）
- 本編・修正版をKOHに送る前に、全シーンを「最初（15%）」「途中（45%）」「最後（85%）」の3枚ずつ並べたシートを作り、1シーンずつ目で見る。数枚の抜き取りで済ませない。
- 割れる・動く・切り替わる演出があるシーンは、その動きの前後を0.3秒刻みで拡大して見る（切り抜きのつなぎ目に細い線が出る等、一瞬だけの不具合を見逃さないため）。直したシーンは修正箇所だけでなくシーン全体を見直す。
- 見る項目：①文字と文字・人・図のかぶり ②画面の端からのはみ出し ③出典メモと見出しのかぶり ④絵がセリフの意味に合っているか（例：大学→校舎、世代→3世代の図。夕日や門でごまかさない） ⑤人が床・階段・線の上にちゃんと立っているか ⑥3Dが雑でないか（雑なら写真や2D図にする）
- 50シーン一気に作るときも、ブロック（約10シーン）ごとに上のシートで確認してから次へ進む。
- **3Dで人や物が動く場面は、必ず0.3秒刻みで全部見る**（2026-11-23 09の改札で、人が改札機の中を通り抜けていたのを見逃した）。見るのは、人が物の中を通り抜けていないか、ループで人が急に消えたり出たりしないか、足が床から浮いたり沈んだりしていないか。3枚だけの確認で済ませない。
- **音のチェック（2026-11-23 11の試作で音声なしを送った）：** 送る前に ffprobe で音声の長さが映像と同じか、頭・途中・終わりで volumedetect の音量が出ているかを確かめる。mux は必ず `-map 0:v -map 1:a` を付ける（付けないと、つないだ映像側の空の音を拾うことがある）。
- 人を通路に置くときは、コードで物の位置（x座標など）と人の通り道が重なっていないか数字で確かめてから書き出す。

## アナリティクスから決めたルール（KOH採用 2026-11-23、research/analytics_2026-11-23.md）
- **ショートには必ず本編への「関連動画」リンクを付ける。** Studioのショート編集画面の「関連動画」に本編を入れる（05のショートは1,040回見られたのにリンクがなかった）。
  - これを使うにはチャンネルの「ワンタイム認証」（高度な機能の確認）が必要。2026-11-23時点で未完了 → KOHが済ませたら、06〜09のショートにも付ける。済むまでは概要欄で本編タイトルを書いて誘導する。
- **冒頭15秒を強くする。** 最初の1文で「問い＋いちばん強い数字」を言う。最初の5秒以内に3D・写真・動画のどれかを入れる（維持率グラフで最初の15〜20秒に約半分が離脱していた）。
- **ネタ選び：** 「身近なあるある（例：地元に若い女性がいない）＋国の統計」を優先する。05がクリック率3.2%・平均視聴3:25でいちばん良かった。
- **公開から約48時間後に維持率グラフを見る。** 冒頭の離脱が減ったか、前の回と比べて research/ に残す。

## 投稿後チェックリスト（RKJ動画から 2026-11-22、research/rkj_48h_2026-11-22.md）
- 概要欄の目次：0:00から・3つ以上。チャプター名に動画のキーワードを入れる（例：「第1章：お見合いの時代」→「第1章：お見合い結婚の時代」）。
- 概要欄の最初の2行にメインのキーワードを自然な文で入れる。
- 固定コメント：動画のキーワードについて質問を促す1文（「あなたの地元に若い女性は残っている？」など）を投稿して固定。
- 再生リスト（テーマ別：恋愛・結婚／地方・人口／見た目／お金と格差）に入れ、リストの説明にキーワード。
- 終了画面：他の本編1本＋登録ボタン。人気が出た動画の終了画面には、伸びていない動画を置く。
- 48時間後：クリック率5%以下ならタイトル・サムネを変える。維持率グラフで離脱が大きい区間を確認。
- 台本：最初の30秒でメインキーワード（例「親の年収」「成績」）を必ず声に出す。締めで次の動画をすすめる。
